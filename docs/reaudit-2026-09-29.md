## Reference decision

The question was how to turn the project screen into inspectable evidence while
keeping the surrounding composition. Compared a permanently larger inline
screen, an expanded viewer, and a shared-element route transition. The viewer
adds playback control and depth without changing the router or adding a library.

The author's [Codrops Grid Zoom explanation](https://tympanus.net/codrops/2021/12/01/grid-zoom-layout/)
and [repository overview](https://github.com/codrops/GridZoom/) document a small
media item expanding into a focused content view. That relationship informed the
choice; no code, grid layout or assets were copied. The live demo returned HTTP
403, so its timing and current interaction behavior were not verified.
[web.dev's dialog guidance](https://web.dev/articles/building/a-dialog-component)
informed the use of native modal focus and Escape behavior. A brief 320 ms
entrance follows the portfolio's existing easing; closing is immediate and
reduced motion removes the entrance.

The existing rotating disk remains the signature. A shader, custom cursor or
another page-wide effect did not provide a stronger connection to the actual
work. The project viewer is an extension of the existing screen material.

## Verification

- Build, lint and `git diff --check` passed. All four routes plus 404 are
  prerendered. No dependencies or media assets were added.
- Chrome: 92 existing motion/layout/fallback checks and 40 focused audit checks
  passed. Five routes covered at 320, 390, 768, 1024, 1440 and 1920 px with no
  horizontal overflow. Ten page accessibility scans and a modal scan found no
  violations. This does not certify complete accessibility.
  Edge also passed all 40 focused audit checks, including the viewer's
  keyboard, history, reduced-motion and failure states.
- Visual inspection covered the opening, project stage, enlarged viewer,
  streamlined About and Experience pages, and footer. The viewer was exercised
  at narrow/intermediate/wide widths and 844 × 390 landscape. Static HTML,
  reduced motion, unavailable animation APIs and failed video were checked.
- Local Lighthouse mobile, production preview: **95 performance / 100
  accessibility / 100 best practices / 100 SEO**; FCP 2.0 s, LCP 2.7 s, CLS 0,
  TBT 0 ms. These are lab results, not field measurements. Production JS:
  **320.09 kB / 99.59 kB gzip**; CSS: **42.65 kB / 9.55 kB gzip**.
- Physical touch/trackpad hardware and Safari were not tested. On narrow portrait
  screens, the recording is still physically small; native fullscreen and
  landscape viewing are the useful paths for inspecting fine interface detail.
